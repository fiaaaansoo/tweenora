## Integration mode

`git subtree` without `--squash`, decided in P0-2 (rationale: `PLAN.md`
§ 3). Each upstream base is marked by a tag `rive-base/<short sha>`.

## Policy (D7)

**Freeze, then follow.** The runtime stays at the base commit until parity
(phase 4). After that, each Rive version is merged, one by one.
Tweenora-specific changes stay minimal (D6) so that merges remain simple.

## Configuring the remote (once per local clone)

The `upstream` remote is not carried over by `git clone`.

```bash
git remote add upstream https://github.com/rive-app/rive-runtime.git
git config remote.upstream.tagOpt --no-tags      # no Rive tags in the repository
git remote set-url --push upstream no_push       # never push to Rive
git config core.longpaths true                   # Windows: the runtime's long paths
git fetch upstream
```

## Merging a Rive version

1. `git fetch upstream`, then choose the target version. Rive's tags
   (`runtime-vX.Y.Z`) are not fetched (`--no-tags`): list them with
   `git ls-remote --tags upstream 'runtime-v*'` and note the `<sha>` of the
   `^{}` line of the wanted version.
2. Create the crew task for the merge and its `chore/<slug>` branch from
   `main` (`CONTRIBUTING.md`), e.g. `chore/runtime-upstream-0-1-560`.
3. Merge into the subtree, in a dedicated commit:

   ```bash
   git subtree merge --prefix=runtime <sha> \
     -m "chore(runtime): merge upstream <short sha>"
   ```

4. Resolve conflicts in `runtime/` only.
5. Check every line of the deviation register (D15), including the guard in
   `runtime/tests/unit_tests/premake5.lua` (it must still be there, one guard
   per folder) and the `TWNR` / `RIVE` signature of
   `runtime/include/rive/runtime_header.hpp` (`[signature]` tests) and the `targetname` of `rive_build_config.lua` (after the build, `out/<config>/` contains `tweenora*.lib` or `libtweenora*.a`). Build and run the runtime unit tests
   (commands verified in `AGENTS.md`, P0-3 and P0-4): the build
   succeeds and the count stays consistent: P0-4 baseline of 2600 listed tests
   (2597 passed after the filter of the 3 D3D tests), plus the tests added by
   Tweenora (P1-1: 4), when `rive_native/` and `texture_compressor/` are
   absent; the 10 cases of these two folders are added if they are present.
   Then the parity tests as soon as they exist (phase 4).
6. Tag the new base:
   `git tag -a rive-base/<short sha> <sha> -m "Base rive-runtime runtime-vX.Y.Z"`.
7. PR to `main` merged by **merge commit** (`CONTRIBUTING.md`), then
   `git push origin rive-base/<short sha>`.

## Pitfalls

- **Never** run `git merge upstream/main` or `git pull upstream`: Rive would be
  merged at the root of the repository. Always go through
  `git subtree merge|pull --prefix=runtime`.
- Tweenora-specific commits (for a future commitlint, which must not check
  Rive's commits): `git log main --not $(git tag -l 'rive-base/*')`.
  `git log --first-parent main` shows only the PR merges.
- Divergence from the base: `git diff --stat <last rive-base/* tag> HEAD:runtime`
  (must be limited to the D15 register deviations and the D6 renames).
- Extracting a separate runtime repository one day: `git subtree split --prefix=runtime`
  (slow, to be done only once). Never `git filter-repo --subdirectory-filter`,
  which would lose Rive's commits whose paths are at the root.
