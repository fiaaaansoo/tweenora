# docs/examples/

Original Tweenora animation examples, **generated by code** (without an editor) for the public demo
https://tweenora-demo.pages.dev. Each file is written by `tools/twno_gen/` from the format specification
and the schema alone: no byte, file or asset from Rive or upstream. The versioned files are `.riv`
(signature `RIVE`); the matching `.twno` is produced with `python tools/twno_convert.py <file>.riv`.

## Regenerate and check

```text
python -I tools/twno_gen/build_examples.py            # rewrites docs/examples/*.riv
python -I tools/twno_gen/build_examples.py --check    # exit code 1 if a versioned file differs from the regenerated one
python -I -m unittest discover -s tools/twno_gen/tests
TWNO_GOLDENS=<fork's goldens.exe> python -I -m unittest discover -s tools/twno_gen/tests
```

Generation is deterministic (same bytes on every run). The scenes are in `tools/twno_gen/scenes/`.
The images in `renders/` (321 x 321, web render of the `@tweenora/webgl2` package, animation frozen with `scrub` on
`web/examples/state-machines/playback.html`) are manual captures (Playwright, no script or `--check` control) meant to be looked at, not
pixel references; the number in the name is the animation frame (60 fps).

## Examples

Palette: teal (`#14907F`, accent of the demo page), indigo and amber; transparent background, readable on both the light
and the dark theme. Square artboards of 400 x 400. The ball and the square contain a looping linear
animation and a `loop` state machine (one layer: entry, animation state): the state machine is what
makes the animation play in tools that only read state machines (`goldens`).

### `bouncing-ball.riv`: bouncing ball

- Artboard `Bouncing ball`, animation `bounce` (96 frames at 60 fps, 1.6 s, loop), state machine `loop`.
- A ball (`Ellipse`, highlight as a tilted `Ellipse`), a shadow and a floor. The ball falls from `y = 90` to `y = 300`
  in 42 frames (cubic ease-in interpolator), squashes on impact (`scaleY` 0.8, `scaleX` 1.2, `y` 308 so that
  the bottom stays on the floor) for 12 frames, then rises in 42 frames (ease-out interpolator). The shadow
  widens as the ball approaches the floor (`scaleX` and `scaleY` from 0.6 to 1.1).
- Demonstrates: `LinearAnimation`, `KeyedObject`, `KeyedProperty`, `KeyFrameDouble`, `CubicEaseInterpolator`, hierarchy
  of `Node` and `Shape`, single-state `StateMachine`.
- Last frame equal to the first for each track: the loop does not jump.

### `spinning-square.riv`: spinning square

- Artboard `Spinning square`, animation `spin` (120 frames at 60 fps, 2 s, loop), state machine `loop`.
- A rounded-corner square (140 x 140) and an amber marker 42 units from the center, in a `Node` that makes one full
  turn (`rotation` from 0 to 2 pi: the unit is the radian), with a breathing scale (`scale` 1, 0.85, 1,
  cubic interpolator) and a color change of the square (`KeyFrameColor` on `colorValue`, teal, indigo,
  teal).
- Demonstrates: `rotation`, scale, `KeyFrameColor`, linear and cubic interpolation.

### `button.riv`: toggle and pulse button

- Artboard `Bouton`, four animations of one frame or short (`repos`, `actif`, `neutre`, `pulsation`), two state
  machines that run alone or together (they do not animate the same properties).
- A button drawn by code: a rounded-corner rectangle (220 x 96) and a round knob.
- State machine `bascule` (default): boolean input `actif`. Two animation states, `repos` (teal, corners of
  16, knob on the left) and `actif` (indigo, corners of 48 hence pill-shaped, knob on the right); transition from
  `repos` to `actif` when `actif` is true, from `actif` to `repos` when it is false, 250 ms of blend in both directions.
- State machine `impulsion`: trigger `appui`. State `neutre` (scale 1) then, on `appui`, state `pulsation`
  (scale 1, 1.12, 1 over 24 frames, cubic interpolator); automatic return to `neutre` through an exit time at
  100% of the pulse (no condition).
- Demonstrates: `StateMachineBool`, `StateMachineTrigger`, `StateMachineLayer`, `EntryState`, `AnyState`, `ExitState`,
  `AnimationState`, `StateTransition` (duration, exit time), `TransitionBoolCondition`, `TransitionTriggerCondition`,
  blending between two animations, animation of `cornerRadiusTL`, of color and of scale.

### `tinted-shape.riv`: shape tinted by a bound property

- Artboard `Forme teintee` (400 x 400), no animation or state machine: a rounded-corner square (220 x 220)
  and a round knob.
- A view model `Teinte` carries two color properties: `accent` (rank 0, amber by default) and `couleur` (rank 1,
  teal by default); the default instance sets their values. Two `DataBindContext` entries (source to
  target, no converter) bind `accent` to the color of the knob and `couleur` to that of the square: changing one
  property changes the corresponding shape, not the other.
- Demonstrates: `ViewModel`, `ViewModelPropertyColor`, `ViewModelInstance`, `ViewModelInstanceColor`, `DataBindContext`,
  `Artboard.viewModelId`. Study and write order: `tools/twno_gen/NOTES_DATA_BINDING.md`.
- The file binds nothing by itself: the host creates the view model instance and binds it to the artboard (the
  web library does it by default, `goldens` creates a fresh instance). In the demo page, it will be up to
  Examples 3a to declare the file; the `accent` and `couleur` properties will be set by hand there.
- Check images (web render, captured by hand): `renders/tinted-shape-initial.png` (default values) and
  `renders/tinted-shape-changed.png` (`couleur` indigo, `accent` teal).

## Checks performed

- Native (the fork's `goldens`, `-b gl`): position of the bottom of the ball, width and center, angle and distance of the marker,
  color of the square measured on the frames at 0, a quarter, half, three quarters and the full duration, compared with
  values computed by hand from the keyframes (cubic curve solved in the test, outside the scene code);
  image at the full duration equal to the image at 0; `.twno` pixel-identical to the `.riv`.
- Particularities of `goldens`: it plays only one state machine (a file without a state machine is rendered at rest),
  the first advance is used to enter the animation state (after N advances the animation is at frame (N - 1)), and
  on this machine the first 383 lines of the 1600 x 1600 image are not drawn (probable cause: window
  limited to the screen height): the bottom of the ball is measured instead of its center at the top of the trajectory.
- Button, native: initial state of the two state machines (rest color at the center, knob on the left, corner radius of
  16); `.twno` identical to the `.riv`. The native build sets no input: the behavior is verified in a browser.
- Button, web (Playwright, `state-machines/inputs.html`, `bringToFront` is essential: without it the driven browser
  slows the frames down): `actif` set to true, after 700 ms the center becomes `(76, 111, 224)`, the knob goes from x = 137 to
  261 (artboard units) and the corner is no longer filled (pill); back to false: return to the rest state;
  `appui`: the width of the button goes from 221 to 246 (x 1.11) then back to 221, states `neutre`, `pulsation`, `neutre`.
- Tinted shape, structure (`test_tinted_shape.py`): order of the objects, rank of the view model, of each property and
  path of each `DataBindContext` re-read from the stream (each binding follows the `SolidColor` it targets and reads the
  property whose instance carries the color of that `SolidColor`); no artboard number for the view
  model objects and the bindings.
- Tinted shape, native: `goldens` binds a fresh instance of the view model (`createViewModelInstance`), not the file's default
  instance: the center of the square is black (default value of a color property), whereas it
  stays teal without the `DataBindContext` entries; `.twno` identical to the `.riv`. The native build therefore does not verify the
  values of the default instance.
- Tinted shape, web (Playwright, `data-binding/values.html?file=...`, captures analyzed with Pillow, reading the
  WebGL canvas being empty): on load, square `(20, 144, 127)` and knob `(242, 184, 75)`, values of the default
  instance; after `couleur = 0xFF4C6FE0` and `accent = 0xFF14907F`, square `(76, 111, 224)` and knob
  `(20, 144, 127)`: each property drives only its shape.
- Demo page (`/demo/`) at 320, 768 and 1280 px: the three files open without error, no horizontal
  scrolling, the two state machines are offered, the `actif` input is displayed and toggles, no request outside the
  domain. The console contains "Could not find a View Model linked to Artboard ..." for any file without a view model
  (also observed with `two_artboards.riv`, an upstream file): library behavior, unrelated to these
  files.
- Web (Playwright, `state-machines/playback.html`): loads without error, looping playback with no console error
  (590 frames in 2.5 s). Web / native render parity belongs to P4-1d.
